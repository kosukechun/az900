# データと静的アプリの設計

## 実行時の構成

GitHub Pages → HTML/JS/CSS・独自JSON教材 → React → 端末内IndexedDB。

ネットワークは初期静的ファイル取得と利用者が開く公式参考リンクだけに使用する。サーバーへの回答送信、認証、分析トラッキングを実装しない。HashRouterで全ページを静的配信する。ビルド時のbaseは環境変数から渡し、PWAとJSONにも一致させる。

## 保存ストア

| ストア | 主キー・索引 | 役割 |
| --- | --- | --- |
| answerAttempts | id、questionId、answeredAt、sessionId、mode | 全確定回答。追記型 |
| questionProgress | questionId、lastAnsweredAt | 最新の未克服状態、誤答回数 |
| studySessions | id、status、updatedAt | 問題順、位置、回答、バージョン、模試締切、見直し、途中状態 |
| bookmarks | id | 問題のしおり |
| glossaryBookmarks | id | 用語お気に入り |
| userSettings | id=preferences | テーマ、問題数、自動遷移 |
| studyGoals | id=daily | 1日の目標 |
| privateMaterials | id=mogimondai、addedAt | 端末内PDF Blob、再開ページ、40問チェック |

IndexedDBのv1に学習7ストア、v2にPDFストアを追加する。v1ユーザー設定には自動遷移秒数を補完する。移行はDexie upgradeで行い、既存履歴は消さない。

## 回答の整合性

1. UIのrefで単一選択を同期的にロックし、即時に判定・解説を表示。
2. `sessionId:questionId` でイベントを識別。
3. 同じイベントが既にある場合は追加しない。
4. 回答追加、該当問題の全履歴から進捗再構築、セッション回答更新を同一トランザクションで実行。
5. 保存失敗はUIに残し、同じ操作を再試行。保存失敗中は次へ進めない。

進捗は回答時刻順（同時刻はイベントID順）で再構築する。端末内の同じ問題の回答が同じミリ秒になる場合は、先行イベントより1ms後を保存し最新回答を明確にする。模試採点は全問題とセッション完了状態を同一トランザクションで確定する。未回答は空の選択肢配列として保存する。

模試の途中回答はセッションにだけ保存し、採点前に回答履歴・復習状態へ反映しない。期限は絶対時刻、一時停止は残りミリ秒で保持する。問題のversionが異なるセッションは現在の正答で採点しない。

## バックアップ

7学習ストアを一貫した読み取りトランザクションで出力し、作成時刻と形式versionを含める。個人PDFは出力しない。形式はZod strictで検証し、不明な項目・版・不正値・重複IDを拒否する。

統合は既存のイベントを主キーで確認して追加。IDが一致して内容が異なる場合は失敗し、トランザクションを戻す。セッションは更新時刻が新しい側、ブックマーク・設定はインポート側を反映する。進捗の集計値はインポート値を信用せず、回答履歴全体から再計算する。

同じ模試セッションを複数端末に配り、それぞれ違う回答で採点した履歴は自動統合できない。衝突として拒否する。端末移行は中断状態を保存してから片方の端末で学習を続けることを推奨する。ブックマーク解除の削除イベント（tombstone）は保持しないため、統合は登録の和集合になる。解除状態も移したい場合はバックアップ後に置換を選ぶ。

## 静的教材と拡張

教材ファイル一覧をJSONで管理し、追加スクリプトで更新する。URLはMicrosoft公式HTTPSに限定。形式検証は追加前・ビルド前・CIで実行する。正答・ライセンスの内容確認は編集者の作業であり、型検証で置き換えない。

用語と問題は安定IDで参照。問題の解説から辞典モーダルを開き、閉じても問題・回答・位置は保つ。全教材を初期ロードするので回答後の解説にネットワークは不要。

## PWA

vite-plugin-pwa / Workboxのprecacheで静的アセットと教材をキャッシュする。新Service Workerは利用者の更新操作で有効化し、古い静的キャッシュを整理する。IndexedDBはSWキャッシュと独立して保持する。個人PDFはpublic、dist、SWへ入れない。
